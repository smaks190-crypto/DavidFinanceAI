# Issue #101 — подтверждение расходов и доходов в Live (часть этапа 3)

## Поведение

Завершённая пользовательская реплика передаётся существующему локальному парсеру.
Для однозначного расхода или дохода приложение показывает сумму, категорию,
подкатегорию и дату. До подтверждения в Room ничего не записывается.
Кнопка «Записать» или отдельная точная команда «подтверждаю запись» подтверждает
текущую карточку. «Отмени запись» и кнопка отмены удаляют предложение.
Обычное «да» не считается подтверждением финансовой операции.

Сохранение использует существующий BudgetRepository и TransactionEntity, в том числе
синхронизацию журнала регулярных операций. ID записи детерминирован из бюджета и ID
предложения. В одной Room-транзакции проверяется существующая запись: повтор того же
содержимого не изменяет её, а иной payload с тем же ID отклоняется. Конкурентные
подтверждения сериализуются. Звук успеха проигрывается после успешного сохранения;
при ошибке карточка остаётся доступной для повторной попытки.

Во время записи предложение нельзя отменить или заменить новой транскрипцией.
Смена профиля инвалидирует ожидающие обработчики; финализация старой сессии при
смене профиля не создаёт предложения в новом бюджете. ID реплик включает случайный
идентификатор экземпляра контроллера, чтобы новые операции после перезапуска не
совпадали с ранее сохранёнными.

## Основные файлы

- `DavidViewModel.kt`: предложения, очередь, подтверждение и отмена, защита профиля.
- `DavidChatScreen.kt`: карточка проверки и состояние сохранения.
- `DavidLiveOperationCommand.kt`, `DavidLiveSessionController.kt`: точные голосовые
  команды, границы реплик и инструкции модели без ложных обещаний записи.
- `BudgetRepository.kt`: атомарное сохранение с проверкой ID и содержимого.
- `VoiceParserHelper.kt`: «позавчера» проверяется раньше «вчера».

## Проверка вручную

1. Сказать «Потратил 450 рублей на продукты». Проверить карточку и отсутствие
   записи до подтверждения.
2. Подтвердить кнопкой; повторить нажатие. Должна появиться одна операция.
3. Для новой операции произнести «подтверждаю запись». Проверить одну запись.
4. Отменить следующую операцию голосом и кнопкой; записей быть не должно.
5. Сменить бюджет при открытой карточке: она должна исчезнуть, в новом бюджете
   не должно появиться старого предложения.
6. Проверить «позавчера», доход, длинную реплику, прерывание, reconnect и ошибку БД.

## Границы реализации

Это завершение базового пути расходов/доходов, а не всего этапа 3 задачи #101.
Долги, погашения и переводы не превращаются в обычные расходы/доходы; отдельный
маршрут для них ещё нужен. Выбор счёта и редактирование карточки не добавлены.
Неоднозначные реплики не запускают Gemini-парсер автоматически. Незавершённые
предложения хранятся в памяти и не восстанавливаются после уничтожения процесса.
Защита повторного сохранения действует по ID операции, пока запись существует;
одинаковый текст новой реплики намеренно не считается дублем старой покупки.
Подтверждение голосом требует отдельной распознанной реплики. Живой Gemini-сеанс
и устройство нужны для проверки реальной сегментации и доступности микрофона при
открытом диалоге.

Локальный разбор и запись не требуют сети. Для получения транскрипции в David Live
по-прежнему нужен Gemini Live; новых платных запросов парсинга не добавлено.
Схема БД не меняется. Инструменты чтения финансовых данных не получают права записи.
