# №101: аудит и первый этап David Live 2.0

Дата: 12 ноября 2026. База: main, `cc3f4f85c609678385e25e0e66e4a05988894d4a`.
Ветка: `feat/101-live-subtitle-lifecycle`.

## Границы этапа

В этом изменении реализован жизненный цикл субтитров и оформление диалогового оверлея.
Финансовые записи, долговременная память и новые графики не реализованы этим изменением.
Ни API-ключ, ни дополнительные запросы Gemini для данной доработки не нужны.

контроллер/аудиодвижок/модели/экран Live, финансовые инструменты, парсеры, DAO,

Существующий `DavidLiveSpeechSyncTracker` использует оценки длительности слов по
аудиосэмплам, а не timestamps слов от API. Это нельзя описывать как точную пословную
синхронизацию. Данное изменение не добавляет новых оценок времени произнесения слов:
fade применяется только к тексту, который уже опубликован контроллером.

## Что изменено в первом этапе

1. `app/src/main/java/com/example/davidapp/live/DavidLiveSubtitleLifecycle.kt`:
   отдельное состояние презентации текста и его автора; удержание 2500 мс после
   завершения аудио; отмена предыдущего таймера по ревизии, включая одинаковые новые
   реплики; повторный completion не продлевает срок. История не затрагивается.
2. `app/src/main/java/com/example/davidapp/live/DavidLiveSessionController.kt`:
   подключён lifecycle; сброс при смене соединения, прерывании и закрытии;
   пользовательский оверлей скрывается при обработке ответа/инструмента;
   завершение обрабатывается только после server turnComplete и drain.
   Пустая очередь между аудиочанками больше не переводит соединение в LISTENING.
3. `app/src/main/java/com/example/davidapp/live/DavidLiveSheet.kt`:
   постоянная область 104/120 dp как в PR #100; пользователь слева, Давид справа;
   появление 220 мс, исчезновение 400 мс; плавное появление добавленного текста.
4. `app/src/main/java/com/example/davidapp/DavidViewModel.kt` и
   `app/src/main/java/com/example/davidapp/DavidChatScreen.kt`:
   роль автора субтитров передаётся отдельно от мгновенного состояния микрофона/динамика.

## Проверка в приложении

1. Открыть David Live с рабочим ключом и задать короткий вопрос.
2. Проверить: своя фраза слева, ответ Давида справа; сфера не сдвигается.
3. Дождаться окончания звука: ответ остаётся примерно 2,5 секунды, затем исчезает
   за 0,4 секунды. Паузы между чанками не запускают скрытие.
4. Во время этих 2,5 секунды начать новый вопрос, в том числе с одинаковыми словами.
   Старый таймер не должен скрыть новую реплику.
5. Перебить длинный ответ; отключить и восстановить сеть. Старый текст не должен
   появляться как новая реплика. Проверить сохранённый разговор в чате.
6. Повторить для встроенной карточки и полного экрана, длинных фраз, небольшого
   экрана и увеличенного шрифта. Свернуть и развернуть Live во время ответа.
7. Выключить микрофон во время ответа: окончание воспроизведения и скрытие текста
   по-прежнему должны работать.

## Проверки и риски

Фактически выполнено: `:app:assembleDebug` — успешно;
`:app:testDebugUnitTest --tests "com.example.davidapp.live.*"` — **78 тестов, 0 ошибок,
0 пропусков**. В том числе 64 существующих теста Live, 2 существующих теста речи,
7 новых тестов lifecycle, 3 интеграционных и 2 проверки Compose-геометрии.
`git diff --check` — успешно.

Новые тесты: `DavidLiveSubtitleLifecycleTest` (виртуальное время),
`DavidLiveSubtitleIntegrationTest` (server completion + локальное аудио + история),
проверки геометрии в `DavidLiveSubtitleLayoutTest` (Compose под Robolectric).

Для проверки локально подготовлены Gradle 9.3.1, JDK 21 и Android SDK 36.1.
Временный Gradle init script перенаправляет рабочий каталог Robolectric и сетевой
прокси в среду задачи; настройки приложения ради сборки не изменялись.
Первый запуск Robolectric был заблокирован недоступным домашним каталогом,
после настройки среды весь указанный набор прошёл.

Инструментальные тесты на устройстве и реальный Gemini Live-сеанс не запускались:
эмулятор не настроен, ADB не смог создать ~/.android в доступной среде.
Robolectric-проверка геометрии не заменяет проверку живого аудио и визуальной плавности
на телефоне.

Основные риски: конкуренция WebSocket/аудиособытий, поздние чанки транскрипции,
геометрия на небольших экранах/крупном шрифте, реальные задержки AudioTrack.
Сетевых вызовов и стоимости Gemini не добавлено. Офлайн-учёт и записи Room не изменены.
PR, merge и запуск GitHub Actions этим этапом не выполняются.

## Что ещё можно улучшить

- Связать success-анимацию с подтверждённым setupComplete и проверить быстрые
  переходы подключения/речи, не добавляя фиктивных этапов анализа.
- Перед записью из Live выделить единое подтверждаемое намерение со стабильным ID
  и транзакционной защитой дублей; сначала исправить неоднозначности дат и переводов.
- Для графиков сделать обязательными проверенные значения вместо демонстрационных
  defaults. Для памяти отдельно определить срок хранения, подтверждение и удаление фактов.
