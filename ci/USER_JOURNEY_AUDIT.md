# David FinanceAI: визуальный аудит пользовательского пути

## Что делает

Workflow **Visual user journey audit** запускает чистый Android-эмулятор Pixel 6
(Android 15) и действительно нажимает элементы в запущенном приложении:

1. Первый запуск — выбор и создание профиля «Личный бюджет».
2. Главная нового профиля: проверка, что кассовый разрыв обозначен как предварительная оценка.
3. Создание расхода 480 ₽ «Поездка на метро» и проверка этой записи в истории.
4. Создание тестового долга «Т-Банк» на 1 200 ₽.
5. Заполнение формы цели «Новый ноутбук» на 80 000 ₽, прокрутка к кнопке создания и проверка сохранённой цели.
6. Просмотр годового отчёта и возврат на главную.
7. Вопрос Давиду о текущем остатке; проверка локального ответа по данным расходов и долга.
8. Открытие настроек и раздела основных параметров без изменения пользовательских настроек.

На каждом шаге сохраняются PNG и Compose semantics (.txt). При ошибке
тест пытается сохранить отдельный кадр `99-failure.png`.
Успешный прогон требует двадцать один скриншот и соответствующие файлы semantics.
При неполном прогоне отчёт перечисляет пропущенные шаги.

Все данные синтетические. CI устанавливает debug-приложение на новый
одноразовый эмулятор для каждого прогона.

## Где смотреть

GitHub → Actions → **Visual user journey audit** → нужный запуск.

- В **Summary** — сколько экранов удалось снять и, при включённом vision API,
  конкретные замечания и предложения для каждого экрана.
- В **Artifacts** → `user-journey-visual-audit` — ZIP с
  `build/user-journey-audit/index.html` (галерея снимков, открывается в браузере),
  `report.md`, PNG, semantics и журналом инструментального теста `instrumentation.log`.
- Снимки собираются **до** выключения эмулятора, а отчёт создаётся
  даже при неудачном тесте, если их удалось сохранить.

Запуск происходит автоматически в PR при изменениях Android-кода,
после изменения `main`, а также вручную через **Run workflow**.

## Настоящая ИИ-оценка дизайна (не имитировать, если API недоступен)

Без визуальной модели скрипт только сохраняет доказательства и отмечает
кандидатов на проблемы с доступными именами по Compose semantics.
Он **не утверждает**, будто оценил цвета, композицию или поведение пользователя.

Для визуальных рекомендаций можно добавить секрет GitHub Actions:

- `VISUAL_AUDIT_API_KEY`: ключ доступа к совместимому vision chat-completions API.
- Необязательная переменная `VISUAL_AUDIT_MODEL`, по умолчанию `gpt-4.1-mini`.
- Необязательная переменная `VISUAL_AUDIT_API_URL`, по умолчанию
  `https://api.openai.com/v1/chat/completions`.

В **Run workflow** выбери ветку `main` и включи опцию `vision_review`.
Запросы выполняются после успешного прохождения сценария. На автоматических
запусках собираются галерея и отчёт по semantics. Для ручной ИИ-оценки
используются только синтетические снимки этого сценария.

ИИ получает картинку и вспомогательное дерево семантики, оценивает
читаемость, иерархию, пустоты, доступность и понятность следующего действия.
Результаты — **предложения**, не автоматические изменения исходного кода.

## Известные ограничения

- Один виртуальный телефон — не проверяются компактные экраны и планшеты.
- Не проверяются TalkBack, голосовые функции и реальные внешние сервисы.
- Тест фиксирует шаги и ошибки; не заменяет ручной UX-аудит.
- Отключение vision API или отказ провайдера не означает, что проблем нет.
- Маршрут пока не проверяет редактирование и удаление операции, создание обязательных
  платежей и голосовые разговоры David Live.
